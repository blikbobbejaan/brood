## 2026-10-02 — a type-system, contracts and AI-docs review: every finding reproduced, then fixed

A review of the lattice, the checker, runtime contracts and the assistant-facing docs, with
every finding reproduced before it was filed (`docs/review-2026-10-02.md`), then fixed in
five parallel workstreams split by file ownership. Each fix has a regression test at the
entry point a caller reaches, sabotage-verified red.

**Crashes.** `Ty::intersect` on two recursive types recursed without bound (a `deftype json`
checked against itself overflowed the stack): a meet pair that repeats now returns a sound
operand, and `json ∩ json` is answered exactly by an inclusion shortcut. A 20 000-link
`deftype` alias chain aborted the checker; past 256 links it reads as `any`.

**The lattice.** Union is an upper bound again (a record is not absorbed by a map shape whose
values exclude it). A projection takes its member's own length, a variadic arrow still
requires its fixed parameters, a length contradicting a tuple arity empties the member,
widening never narrows a subtraction or an arrow's domain, a bare `pair` parameter is no
longer consistent with everything, `map ∩ map` is exact, and `to_source` declines where it
cannot be faithful. Types are canonical across a new law corpus (`types/tests.rs` checks
reflexivity, transitivity, bounds, commutativity, absorption and `mutual ⊆ ⇒ ==` over lengths,
intervals, literals, list shapes, records with `map_kv`, optional/rest arrows and μ types).
A record instance is ⊆ `map<K,V>` over its declared fields, its hidden `:__id__` excepted —
as `keys`, `count`, `seq` and now the runtime contract all read it.

**Inference.** Loaded recursive closures get a widened self-ascent instead of a ⊥ self-call;
`merge` with an open later argument, `cons` onto a vector, `seq` (kind by kind over a union),
`range` with a step, record `count`/`keys`/`vals` and `nth` with a default match the runtime.
A guard alias dies with its target's rebinding; int-closed arithmetic is precise only over
precise operands; field truthiness and `contains?` select among closed-record alternatives;
`&optional` parameters get domains; keyword callbacks are checked; a lambda passed to an
arrow parameter is typed under that arrow (no strict false positive on `(fn (x) (+ x 1))`
against `(int -> int)`), and an immediately-applied lambda checks its arguments and arity.
Stale rule keys (`distinct`, `sin`/`cos`/`tan`, bare `quot`/`rem`/`mod`, `vector-length`,
`print`/`println`/`format`) are renamed, and `rule_heads_are_bound` fails if one goes stale
again. A same-file `number` function is re-typed under int arguments and `%add`/`%sub`/`%mul`
close like `+`/`-`/`*`, which removed the prelude's own `(inc slash)` false positive. The
soundness oracle now checks intervals, lengths, set elements and μ types.

**Lints.** `try` bodies are checked; only `error-of`/`assert-error` keep the KI-67
suppression, recognised by their expansion's shape. It found real defects in six std modules
(`dns` short reads, `serve`'s attach with no session, `codemod`'s nil root, and three smaller).
A dead clause is reported once, under `:unreachable-clause`; non-exhaustive literal matches,
no-method calls and arity errors gained `:type-mismatch` as their opt-out (they had none).
The `nest check` cache fingerprints the dispatch registries' content, so an impl added in
another file re-checks the file that declares the ability; the ability registry is filtered
to the file's own world, so a multi-file verdict no longer depends on order. Sealed-match
exhaustiveness forgets rebound names; `impl` ops read list parameter forms; variadic
behaviour ops accept any provider arity; the recursion and guard-effect lints respect
scope. `brood --check --strict` exists.

**Contracts.** Contracted non-tail recursion died near 4k levels armed against 200k unarmed:
the JIT's stack margin equalled `vm_apply`'s native reserve, so once the JIT declined a level
the VM refused it too. The JIT margin is 1 MiB, asserted at compile time to stay at least
twice the VM's. A shim declared `-> any` tail-calls the original; a return-checked shim
cannot, which is KI-216 (deferred — it needs a collapsing pending-check frame). `type-matches?`
reads a record name and a sealed ability nominally, as the checker does. Contract frames are
machinery in traces and positions. A thrown `{:kind <k> :message …}` map of a non-built-in
kind renders as `error: <k>: <message>` instead of the whole map. `seq/zip-with` is
data-first: `(zip-with a b f)`.

**Docs.** The writing-brood and brood-debug skills, `brood-for-claude.md`, `language.md` and
`error-codes.md` were re-verified against the binary and corrected (`spawn` of a `fn` does
run; `spawn-monitor` instead of the spawn-then-monitor race; `(doc inc)`; `:requires [A]`;
`lambda` is retired; eight special forms; deep recursion is a catchable E0044). Thirteen
citations of ADR-058 (GC) for mailbox-delivered window input now cite ADR-059.

**HEAD's CI was red, and is fixed here.** The v0.35.0 run failed two jobs. *Clippy (all
features)*: rustc 1.98's `clone_on_copy` and `extend_with_drain` in `process/message.rs`, and
an E0509 in `gui/backend/input.rs`'s test (moving a vector out of `Message`, which became
`Drop` for the iterative free) — taken with `mem::take`. *Tree-walker differential*:
`robustness_limits_test` "match, fn, let and receive all refuse it up front" — `receive`'s
pin and tag scans walked a 100 000-level pattern without a bound BEFORE the lowering cap
refused it, which exhausts the tree-walker's stack budget while the VM's heap frames
survived to the refusal; `receive` now calls the shared `%match-refuse-too-deep` before any
scan. And `sse_test` "a refused connection…" picked a port, released it and connected,
racing any parallel test's server for it — it connects to port 1 now, which no test process
can bind.

**Not done here:** KI-216; a caught contract error still carries no `:file`/`:line`/`:trace`
(adding them would break "what you throw is what you catch" for one kind — a design call);
`(map xs :kw)`, `comp` and `apply` callbacks are unchecked; a destructured `[tag v]` does not
narrow a record union. `exec_chunk.rs` and `jit_runtime/support.rs` changed near the call
path, so `make ab` and `make ab-vm` are owed on a quiet machine.

## 2026-10-03 — bedit's strict ratchet, and KI-216 closed (ADR-396)

`strict_ratchet_test` (zero `nest check --strict` findings) read four — five at bedit's
HEAD. All five sat inside `try` bodies, which the 2026-10-02 review started checking. One

declared `-> (or nil (vector (or map number string)))` for a value that is always

tests are green against this tree; the full suite is CI's.

**KI-216.** A return-checked contract shim calls its original in argument position, so a
chain of contracted tail calls kept one suspended shim per call — `(int -> keyword)`
ping/pong hit the 1M frame cap armed and ran flat unarmed. The deferred fix was "a VM frame
kind that records a pending check"; it turned out a suspended shim already IS that frame,
and what was missing was a way to recognise one. The templates now call the original
inside `(%contract-await ret …)`, a `Prim2` mark whose resume point identifies the frame
and whose first operand — directly below the callee's frame — is the type it will check.
Before calling, `(%contract-tail? ret)`, a `Prim1` whose VM arm exits to the driver,
answers whether the frame this activation returns into is such a mark with an `equal`
type; if so the shim tail-calls. The tree-walker and nested runs answer `false` and keep
checking; both ops keep shims off the JIT. Nothing on the ordinary call path changed.

Guard `return_checked_tail_calls_collapse_and_still_check`: 2M levels at tiers 1 and 2,
a violation at the bottom of a chain, and a narrower type at either end of a chain.
Sabotaged both ways — never collapsing reds the flat case at tier 1, always collapsing
reds `narrow-inner` (it returned 3 unchecked). `contract_test` 115/115 at tiers 0/1/2
armed; the contracts cli/nest integration binaries, the prim unit tests, clippy on CI's
flags, rustfmt and `nest format --check` clean.

## 2026-10-05 — the checker residue from the 2026-10-02 review, closed

**`:only` names.** `(:use m :only [typo])` warns at the clause, naming the module and the
missing name — the half of KI-211 the runtime could not take (a module may be mid-load or
image-backed at refer time). Silent when the module could not be loaded at all.

**Callbacks.** Four shapes were never checked against what they are handed:
- a keyword — `(map ps :x)` now types as `(:x p)` per element (`infer::callback_ret`);
- a NAMED function — only `fn` literals were ever seeded with the element type, so
  `(map xs inc)` over strings was silent. A named, keyword or composed callback is now held
  to the same seed by disjointness, except over a record collection, which may iterate
  itself through `Seqable` (`record_test`'s `stack` was the false positive that showed it);
- `(comp f g)` — a signature composed from its stages, plus a finding when a stage returns
  what the next cannot take;
- `(apply f … xs)` — `f`'s fixed parameters against the leading arguments and the spread
  collection's elements.
`domains::a_permissive_higher_order_stdlib_callback_stays_silent` had pinned the old silence
on `(map [1 2 3] string/length)`, a program that raises; it now pins the finding.

**Narrowing.** The return check (`gradual_of`) recorded neither the path alias nor the
symbol alias a `let` makes, so every `match` over a tagged-tuple union with a declared
result read each arm's binder as the union — a strict false positive. And a destructured
`(let ([tag v] r) (if (= tag :ok) …))` never narrowed `v`: the matcher binds `tag` through
a temp, so the guard reached the path only via an alias, and `v`, bound before the guard,
never saw the base narrow. `narrow` now applies path narrowing to every alias the chain
reaches, `narrow_path` re-narrows the base's other positional aliases, and the three `let`
binders share `bind_pattern`.

**Smaller.** A finding inside a clause `match` copies into two branches was reported twice;
identical (position, message) pairs are now one. `defrecord` refuses anything after the
field list but `:derives [...]` — `(defrecord pt (x int) (y int))` defined fields `x` and
`int` and dropped `(y int)` silently.

Verified: `nest check` and `--strict` exit 0 over std/tests/examples and over bedit;
`types::` 692/692 with the new `check/tests/callback_shapes.rs`; the checker-facing `.blsp`
files green.

**Later the same day — the sabotage pass, and positioned contract errors.** All eight
`callback_shapes` guards were broken in three batches (keyword arm, `apply`, `comp` stage,
de-duplication and the `Seqable` guard; then the named-callback seed, the return check's
path alias and the sibling re-narrowing; then the alias-chain narrowing alone): each batch
reddened exactly the tests it targets and no other.

A caught contract error now carries a position. It was an ordinary `throw` of the policy's
map, so a `catch` saw no `:file`/`:line` where every built-in error has them; adding them at
the catch sites by `:kind` would have changed what a program's OWN `:contract`-kind throw
comes back as. Instead the policy raises through `%contract-raise`, which codes the error
`E0080`; a user `throw` never carries a code, so `LispError::caught_value` — now the one rule
the three catch sites share — enriches exactly those. Both halves of that are tested in
`contract_test` and both sabotage-verified (skip the enrichment: the position test reds;
enrich every map: the user-throw test reds). Under the tree-walker the position is the raise
inside `std/contract.blsp` rather than the user's call — only the VM filters contract
machinery out of positions (`is_contract_arm`); the caught map had no position at all
before, on either engine.

## 2026-10-08 — a whole-project review: forty-odd defects reproduced, then fixed

Six reviewers read every layer at `0f5ff008` — heap/GC, VM + JIT, scheduler + distribution,
builtins + host bindings, reader/checker/LSP, the stdlib — each reproducing a finding (or
tracing a concrete path, marked plausible) before filing it. Seven workstreams then fixed them
in this working tree, split by file ownership, each fix with a regression test at the entry
point a caller reaches and each test sabotage-verified red. The per-finding record — finding,
fix, guard — is `docs/review-2026-10-08.md`; this entry is what it taught.

**Security first.** A dependency named `..` made a re-fetch `%rm-rf` the project itself: the
guard asked only that SOME path component be `_deps`, and no entry point (manifest, fetched
manifest, `nest add`, registry JSON) validated a name. Both layers are fixed — names are one
plain component, and `%rm-rf` refuses `..` and anything not strictly inside `_deps`. The
distribution handshake interned a peer's claimed node name before checking its MAC, so junk
connections could exhaust the wire symbol budget for good; the name is now bytes until
`ct_eq` passes. The HTTP server trusted framing (no body cap, `Content-Length` overrun kept,
`Transfer-Encoding` ignored, workers dying without a response); markdown's scheme filter and
`sse/frame` were injectable; `registry-install` took `file://`; wasm handles were guessable
and outlived their process; PBKDF2 truncated its iteration count to one round.

**Silent wrong answers, which is the class that matters most here.** A self-tail loop called
through an alias after a rebind ran the old body at tiers 1 and 2 — the hot-reload guard
assumed the name meant this arm when the frame began; frames now start at a sentinel epoch so
the first back edge checks (the native tier refuses such an arm, `self-loop-name-rebound`).
The linear-map rewrite accepted any value at the accumulator slot, so a loop that reset to
`{}` crashed. A closure as a map key was lost at the first collection because its hash was
handle bits a move rewrites — closures now carry a move-stable `identity`. The tree-walker's
`let` let a closure see a later binding. A self-reported "ok" from `agent/update` preceded the
update that killed it.

**What the gates missed, and why.** Every one of these was reachable from ordinary Brood; the
suite stayed green because each guard tested the piece its author wrote rather than the
caller's entry point — KI-97's quiet-subscriber reaping was tested by calling `clear_if`
directly while the death path never called it, and the tree-walker `let` bug is invisible to
`brood --test` at `BROOD_TIER=0` (test bodies do not reach the tree-walker), so its guard is
the Rust differential. The checker's new reserved-name lint passed its own tests and put 229
warnings on the prelude's own definitions — caught only by running the project's zero-warning
gate, not the feature's tests, the KI-106 lesson again; `boot::PRELUDE_PATHS` (pinned to
`PRELUDE` by a test) now tells the checker which files define those names.

**Breaking.** `proc/register` binds nothing for a dead pid. It briefly also refused a name a
live process held; that was reverted before landing, because every one of the 22 callers
(six in std, sixteen in bedit — a restarted logger, a test standing in as `:editor` and
handing the name back) registers precisely to take the name over. `csv/decode` raises on
an unterminated quote or junk after a closing quote. `%rm-rf` refuses `_deps` itself. Wasm
handles are opaque tokens. `proc/system-monitor` of a dead pid raises.

**Not done here, by decision:** inbound socket backpressure (a design question — the
recommendation is an explicit re-arm mode, as an ADR) and preferring a restarting peer's new
link (it would also tear down live links). Both are argued in the review record.

**Perf gate needed elsewhere** (no benchmarks on this machine): the self-call fix touches
frame entry and the first back edge per activation, and every closure creation now draws an
identity from a thread-local block — `make ab` and `make ab-vm` before this ships.

## 2026-10-09 — the cleanup: dead flags, one tier knob, Brood-only tooling, docs archived

A whole-project review (eight areas) and a cleanup of everything it found: latent bugs, dead
switches and code, duplicated logic, giant functions, misattached docs, tooling in a language
the project does not use, and documentation that had become a second devlog. Every bug fix
below carries a regression test that was sabotage-verified (fix reverted → red → restored).

**Bugs fixed.**
- *Kernel:* `reset_local_to` dropped the source positions of OLD-generation pairs (the age bit
  at bit 32 was discarded by the retain); a failed `%std-image-reinstall!` replay no longer
  counts as a good imaged boot (falls back to source); a string blob can no longer be built
  from raw bytes (`SharedBlob::from_text` vs `new` — the `from_utf8_unchecked` safety argument
  was false); the image directory's capacity is capped by the bytes present.
- *Checker:* a bare `(fn)` argument inside a `:pure` function panicked (`properties.rs`).
  And the checker could fail to terminate (pre-existing; exposed when the sharper derivation
  built a recursive parameter type for `mcp_test`): unrolling a `μX` type for a subtype or
  disjointness question rebuilt its unions CANONICALLY, which asked more subtype questions of
  the same type, each with a pair the cycle guard had not seen — exponential in the number of
  alternatives. Relations now unroll with unions written as they stand
  (`unroll_for_relation`), and a hard backstop (`MAX_REC_UNROLLS` per outermost question,
  answering the sound "no") guarantees termination even if that regresses.
- *Processes/net:* `tcp/connect` resolved and dialled (10 s per address) ON a scheduler
  worker — now a helper thread, the Brood API still synchronous, failures still `E0050`; a node
  listening on `:0` advertised port 0 (now the bound address; a wildcard host advertises the
  node's own host); each exit swept NAMES twice and scanned every socket/subprocess/wasm
  registry (now one sweep and an owner index, O(owned)); `PARKED_COUNT` was Relaxed in a
  two-sided handshake (a lost wake on weakly-ordered CPUs).
- *std:* `format`'s file walker followed symlinks (a cycle never terminated) — five
  hand-rolled walkers are now `file/walk-files`; `dns/lookup` leaked its socket on every
  failed lookup; `csv` dropped a final `""` row and every bare `\r` inside a field;
  `gen/call-timeout` delivered a second reply after success; `string/blank?` was O(n²).
- *Tooling:* `nest publish` shipped `tests/` and the lock file (the `./`-prefixed tar excludes
  never matched `git ls-files` paths); `publish --bump` published after a failed git commit;
  the version bump edited the first `:version` in the text, not the project's; `nest ws`
  always exited 0; `nest run FILE -h` printed nest's usage instead of passing `-h` to the
  program; `nest test` decided failure by matching message text (now a structured
  `:suite-failed`); MCP `run-tests` and `nest test` discovered different test sets.
- *LSP/builtins:* checker findings with no position were dropped by the LSP; ~90 error labels
  named functions that no longer exist (now a test pins every label to a callable name);
  `%untar-gz` refused nothing (now rejects absolute, `..`, symlink and hard-link members); a
  corrupt release bundle silently ran as plain `brood`.
- *Gates:* `scripts/check-examples.sh` passed "10 failed"; `perf-brood`/`perf-symbols`
  overwrote the timing binary (now `target/release-perf/`, `target/release-symbols/`).

**Follow-ups (2026-10-12).** `seq/vector-ref` / `seq/vector-length` are deleted in favour of
`nth` / `count` (ADR-398, in the rename ledger). The LSP's "did you mean" ranking is Brood —
`fuzzy/edit-distance` and `fuzzy/nearest` — and the Rust Levenshtein is gone. bedit's two
leftovers (`%append-two`, `lineedit-init`'s ignored second argument) are fixed on bedit's side,
so both are removed here: `lineedit-init` is `(prompt history &optional opts)`. **bedit must
be pushed and `BEDIT_REF` moved with this change** (`make smoke-bedit ARGS=--bump`).

**Behaviour changes to know.** A `throw` inside an MCP tool handler reports only
`{kind, message}` in `error.data` (Brood's `catch` binds the value, not its position).
`package/bump-version` takes `(root level)`; `project-collect-tests` is `collect-tests`.
`%random-token`, `%print`, `%coverage-reset`, `%scope-live-pids` and `%mcp-progress`
are gone, as is the per-process eval deadline (MCP's Brood dispatcher kills a handler process
instead).

**Structure.** `jit_lower_arm_inner` 2 077 → ~560 lines; `check_forms` is a list of named
passes in run order; `seq_aware_call_ty` is one `match`; `check_into_inner` 882 → ~170; the
ability/multimethod walkers are one scope-aware walker (which now also sees calls in vectors
and under computed heads); deopt reasons are a `DeoptReason` enum with unique codes (the trace
prints names); one integer-arithmetic emitter; the heap verifier ~440 → ~240; the test-only
single-space collector is deleted; `handle_cmd`/`establish` are split; ~20 bespoke env
toggles moved into `debug_flags.rs`. Not done, deliberately: the two message-copy walkers
(they decline differently on a hot path that cannot be measured here) and `doc-catalog`
generation (its categories are editorial).

**Flags removed** (each with its read, its old code path and its catalogue entry):
`BROOD_VM` and `BROOD_NO_JIT` (the aliases — **`BROOD_TIER=0|1|2` is now the only tier
knob**), `BROOD_XADMIT`, `BROOD_MKCLO`, `BROOD_FLOAT_VETO`, `BROOD_XCALL`,
`BROOD_NO_DEOPT_RESUME`, `BROOD_NO_INLINE`, `BROOD_NO_LEAF_INLINE`, `BROOD_NO_PARTIAL_LEAF`,
`BROOD_NO_FLOAT_GLOBAL`, `BROOD_NO_SHARED_ARMS`, `BROOD_SPAWN_RR`, `BROOD_NO_MSGTAG`,
`BROOD_NO_HANDOFF`, `BROOD_NO_STEAL_WAKE`, `BROOD_NO_IDLE_BACKOFF`, `BROOD_TEST_NO_SCOPE`,
`BROOD_NO_SHARE_FN_MSG` (folded into `BROOD_NO_SHARE_FN`); `BROOD_COMPILE_TRACE` is renamed
`BROOD_TRACE_LOWER`. CI's tree-walker job, `make test-both`, the fuzz runner and the docs use

## 2026-10-12 — the cleanup's follow-through: tcp/close, error positions, the last curated overlap

- **`tcp/close` on a listener is synchronous.** It only queued the close on the reactor, so
  for a moment after it returned the listener still accepted — a peer could connect to a port
  the program believed closed. The listener fd is now shared by the registry entry and the
  reactor (`ListenerSlot`); `close` empties and closes it on the calling thread, and the
  reactor treats an emptied slot as gone. No blocking round-trip, so the worker never waits.
  Guarded by 300 close-then-connect rounds in `tests/tcp_test.blsp` (red 3/3 with the queued
  close restored, on one core). Streams are unchanged on purpose: a closing stream keeps
  reading through its linger so `send` + `close` never truncates a response.
- **A raise inside a `nest mcp` tool reports where it came from again.** `catch` binds the
  thrown VALUE, so a thrown string had nowhere to carry its position once the dispatcher moved
  into Brood. New kernel primitive `(%try-described thunk handler)` calls
  `(handler caught description)`, the description being the full
  `{:kind :message :file :line :col :trace}` map for ANY thrown value; MCP's error mapping uses
  it, so `error.data` carries `file`/`line`/`col`/`trace` for user throws as it did in Rust.
  The compiler only inlines one-parameter handlers, so the VM's catch path is untouched.
- **No curated signature duplicates a std declaration.** The derivation now types a
  self-call's arguments under the function's own parameter demands (the induction step: the
  calling activation was itself entered inside that domain), which proves `keyed-loop`'s
  `(- i 1)` an int; `nest/main` declares the fact only it knows, `((list string) -> int)`.
  With those, `math/even?`, `math/odd?`, `string/starts-with?`, `string/ends-with?` and
  `index-of` leave the curated table and `no_curated_name_is_declared_in_std` admits no
  exceptions.
- **The dated-comment sweep is finished** across `std/` and every crate (~810 more lines):
  history became the rule and its reason; invariants and safety arguments stayed.
- Proven: the distribution suite 3× on four cores, eight concurrency-heavy files under
  `BROOD_GC_STRESS=1 BROOD_GC_VERIFY=1`, a fuzz-differential pass (180 programs, six
  generators, zero divergences), the network files 90× across tiers and boot paths, both
  checker gates at zero, and bedit's three gates.

## 2026-10-12 — the cleanup's last four: tcp/close silence, one copy walker, devirtualization on, a derived doc catalogue

- **`tcp/close` silences the socket at once.** A closing stream lingers up to 5 s to flush
  queued output, and during that time the old owner could still receive inbound data and a
  late `[:tcp-closed]`. Each socket now has one owner record; every delivery goes through it
  under its lock, and `close` clears it under the same lock before returning, so nothing new
  for the socket reaches any mailbox once `tcp/close` returns. Queued output still flushes
  (send-then-close never truncates); bytes read meanwhile are discarded and their flow
  credit returned. The rule covers TLS streams, listener accepts, failed dials and the
  reactor-death sweep; `close` itself sends nothing. Guards: `tests/tcp_test.blsp` (8 MiB
  linger, 6 rounds; nothing queued, 30 rounds) and `tests/tls_test.blsp` (mid-request close)
  — the linger and TLS guards sabotage-verified.
- **One message-copy walker.** `to_message_rec` (Value → `Message`) and
  `copy_cross_heap_rec` (the L1 parked-receiver copy) were the same traversal written twice.
  They are `copy_value<T: CopyTarget>`, monomorphised over `IntoMessage` and `IntoHeap`;
  every difference (budget charging, up-front size checks, refusal as an error vs a silent
  decline, failures, closures by handle, builtins in image mode, list positions) is an
  `#[inline]` trait method, and refusals build their error lazily, so each path compiles to
  its own walker with no runtime mode test. The L1 vector arm no longer copies the element
  array. New `decline_tests` pin each asymmetry; the depth limit had no test before.
- **Ability devirtualization is always on; `BROOD_MONO` is gone (ADR-182/398).** Turning
  it on found five ways the opt-in rewrite disagreed with the op's own dispatch (KI-223).
  The rewritten head is `%dispatch-proven`, which re-checks the op's and constructor's
  definitions on every call and falls back to the op itself; calls with user-code
  arguments, rebound or wrapped op names, rejected arities and contract-armed runs are not
  rewritten. `crates/cli/tests/devirt_differential.rs` compares tiers 1 and 2 with the
  tree-walker. The trace is `BROOD_DEVIRT_DBG`. Tier 2 stays deferred; the performance
  effect is unmeasured here (a rewritten call trades the op's frame and `%identity-of` for
  one primitive with two cached reads).
- **The doc catalogue derives categories.** `std/tool/doc-catalog.blsp` no longer lists
  ~600 names by hand (695 → ~205 lines). A qualified name takes its module's category, a
  bare prelude name the category of the `;; ---- section ----` header above its definition,
  a kernel primitive a small table; 3 exceptions remain. `tests/doc_catalog_test.blsp`
  replaces the hand-list gates: every public name gets a category, every section key
  matches exactly one header, an exception must disagree with its section. Five names moved
  (`any?`, `every?`, `includes?`, `vec` → collections; `contains?` → maps). The prelude's
  source copy falls back to the temp dir when the cache dir is read-only, since categories
  now depend on its definition sites.

## 2026-10-12 — preemption reaches every shape of running code; nine latency and stability defects closed (ADR-400..405, KI-230..238)

The brief: "latency and stability is more important than pure performance — it has to be as
stable as can be." The brood-benchmarks `latency` row (20k req/s open loop, every 20th request
holding its worker ~500 µs) read p99 83–95 µs but p99.9 446–1 539 µs and max 2.3–4.1 ms run to
run, against Elixir's 66 / 213 µs. `BROOD_STALL_MS=1` showed a quantum over 1 ms for nearly
every fat request. Each finding below was reproduced, fixed and guarded in that order.

- **`try` bodies ran nested (KI-230, ADR-400).** `Inst::TryCatch` evaluated the body through
  `exec_value`, which the driver cannot capture: a loop in a `try` was one quantum at every
  tier and a `receive` in one blocked its worker — every `http/serve` handler. `try` is now
  bytecode in the arm's chunk (`TryEnter … TryExit`), with the catch in the driver
  (`catch_in_driver`, out of line: inlined at the driver's ten raise sites it cost `ring` 8%
  of its IPC).
- **Native code was preemptible only at a back edge the driver itself entered (KI-231,
  ADR-401).** Under a native caller a callee's preempt re-ran it on a nested interpreter: after
  500 warm spawns a 2.5 ms loop ran as one 10 ms quantum. A preempt now unwinds the native
  activations into interpreter frames: each caller's error path writes an in-call journal to
  the top of `roots` (a side record — a first version used the frame's checkpoint journal and
  gave pure self-recursive arms that area, which cost `bintree` 10%), a per-thread unwind
  record names the activations, and the driver rebuilds them. An entry reduction poll covers
  native recursion. Activations that cannot unwind keep running native (they used to deopt
  into an interpreter that could not preempt either). Residual by design: the unboxed register
  worker (demoting it costs ~45× on `fib`).
- **Preempt only for someone.** Unwinding a native stack, or stopping and re-entering a fold,
  is costly; with no process queued anywhere it buys no latency. Both now ask
  `scheduler::work_waiting` (one relaxed load) and otherwise run on as a fresh quantum, the
  `:long-schedule` timer restarted. Single-process compute rows stopped paying for preempts
  nobody needed (`json` +5.9% → +1.5% instructions).
- **`binding` bodies ran nested too (KI-232, ADR-402)** — inlined as `BindEnter … BindExit`,
  restored by truncation on a catch or a driver exit.
- **Vector/range folds were one quantum (KI-233, ADR-403)** — owed preemption, and resumable
  `%vector-reduce` / `%range-reduce` that stop between elements. Their primitive loops run in
  spans bounded by the inner loop's own compare: `reduce` reads 23% fewer instructions than
  before.
- **A process re-queued behind a long quantum waited it out (KI-234)** — at a 200-reduction
  quantum the median request waited 2 144 µs. Bounding the quanta fixed it (15 µs). A peer
  wake on every such enqueue was tried first and reverted: `supervisor` +12%, no latency
  gain once quanta were bounded.
- **A stale inlined native survived a redefinition (KI-235)** — found because `undef_test`
  failed 10/10 on the binary from before this work: the compiler stored a lowering that
  finished after the arm was reset, and its dedupe map stamped it with the new epoch.
- **`spawn` promoted each closure into the shared region (KI-236, ADR-405)**: the region's
  collector held the `promote_lock` writer for 100–300 µs; spawns now copy captured values
  into the child and keep the code shared.
- **A set, ratio or decimal literal put its function on the tree-walker for good (KI-237)** —
  the crash reporter's quantum never ended because `take-over` folds into `#{}`.
- **A run-check verdict recorded without the stdlib image replayed its loads forever
  (KI-238)** — after a `std/` edit a trivial program booted in 148M instructions instead of
  81M until the cache entry aged out; it read as an 8% `nqueens` regression until traced.
- **`:long-schedule` (ADR-404)** in the system monitor, and `make latency-gate`
  (`stress/latency_probe.blsp`, the benchmark box's tail gate).
- The sampling profiler samples a native loop that cannot yield (it used to see it only
  because such loops fell back to the interpreter every quantum).
- **Base RSS +27% in the brood-benchmarks refresh was transparent huge pages**, not memory:
  +1% with `MIMALLOC_ALLOW_THP=0` (docs/benchmarking.md §1.5).

**Result** (A/B against v0.37.0, `scripts/ab-bench.sh --floor`, flagged rows re-run alone
best-of-11): `latency` 4 789 → 2 551 ms (−47%); `make latency-gate` worst p99 115 → 80 µs;
at a 200-reduction quantum p50 86–3 263 → 15 µs. `reduce` −10%, `loop` −6%; `fib`, `pfib`,
`nbody`, `sort`, `supervisor` level. **Open cost:** `nqueens` +4.7%, `ring` +5.0%,
`bintree` +3.8% — instructions +1.6%, ~+1% and +4.6%; the remainder is lower IPC, not yet
attributed. Gates: `make test-both` 1829/1829 on both engines, `make gcstress` clean, fuzz
13 generators × 100 (1 900 programs) 0 divergences / 0 crashes / stale=0, clippy
`--all-features` clean.

## 2026-10-13 — a runtime-stability pass: per-runtime state, timed tests, a soak, and running out of descriptors

With nothing open in `known-issues.md`, the pass went after the classes behind recent reds
instead of single bugs. Four lines of work, three new known issues found and fixed.

**Per-runtime state (KI-226).** KI-224 moved three process-wide statics onto `RuntimeCode`;
an audit of the rest found two more holding one runtime's facts. The module resolver's
"failed to find" memo depends on `*load-path*`, so a miss in one runtime made another — whose

## 2026-10-13 (later) — the fold span result stops allocating; a comment moves instruction counts 2%

Handoff item B. `%vector-fold-span` / `%range-fold-span` returned `[acc next]`, a vector
allocated on every fold although almost every fold is one span. A span that finishes now
returns the accumulator itself; one that stops short (4 096 elements, or a preemption owed
between two elements) returns `(:%fold-more acc . next)`, and `fold` tests `pair?` then the
tag. The walk helpers take that continuation directly. `reverse`'s vector branch called
`%vector-fold` with the old signature and now goes through `fold`. ADR-403 updated.

- **The tag.** The first cut tagged with the span native itself, read in Rust by a global
  lookup: `env_get` per stopped span, and `%eq` on two natives runs the structural `equal`
  (~95 instructions). A keyword is an immediate compare. Neither is unforgeable — a private
  prelude def is reachable by name (`%fold-span` reads 4096 from user code) — so the bar is
  "no accidental collision", which an internal keyword meets.
- **Numbers** (`instructions:u`, stdimage live on both arms): `nqueens` 1 204.1M → 1 188.9M
  (−1.3%); a micro of 2M one-span folds −2.7% (~145 instructions a fold); `reduce`, and a
  200M-element range, flat. The stopped-short path costs ~150 instructions more per span than
  the vector did (two pairs, and three `first`/`rest` that are runtime callbacks in this arm —
  it calls a native, so no pair bases are hoisted), once per 4 096 elements.
- **Smaller than the handoff's 5%.** That figure was against the resumable version, which had
  no Brood walk at all; the vector was only part of it. `Reducer::resolve` per span
  (`reduce_prim_op`: `select_arm`, the passthrough map clone, `env_get`, the native-name match)
  is the next per-fold cost, but it did not register in a sampled `nqueens` profile, where the
  JIT arms, `hof_apply_step` and `fill_captures` dominate — item A's territory. Left alone.
- **Measurement lesson.** A control build — HEAD plus one comment line in `core.blsp` — moved
  `nqueens`-class rows by up to 2.3% and boot by 0.7M instructions against HEAD, with no
  semantic change; the same full-source boot agreed to 0.06%. Instruction counts are not
  layout-proof across builds (hashing, allocation addresses, the image's own hash). A delta of
  a few percent between two builds needs a control build of its own before it means anything;
  per-operation costs measured inside one build (an amplified row such as `%fold-span` rebound
  to 1) are the reliable figures.
- **Tests:** `tests/sequence_test.blsp` gains a multi-span fold (vector, range, negative step,
  an accumulator shaped like the continuation but untagged) and a concurrent one (eight workers
  folding 30 000 elements with a closure, so spans stop mid-way under preemption). Sabotage:
  dropping the continuation reds both; a mid-span stop that skips one element reds the
  concurrent test 3/3. A fold program at `BROOD_TIER=0|1|2`, with and without
  `BROOD_GC_STRESS=1 BROOD_GC_VERIFY=1`, `BROOD_REDUCTIONS=100` and `%fold-span` rebound to 3
  (ranges to `i64::MAX`, negative steps, BigInt promotion): identical output on all six and
  equal to HEAD's. `preemption_shapes.rs`/`preemption.rs` 10/10.
